# 一程随行（along-trip）行程规划项目改造方案

> 本文档是项目协作中枢。任何 AI 角色 / 开发者接手本项目，**先读本文档**，再按「任务分解」章节领取任务执行。
> 最后更新：2026-08-12

---

## 1. 项目概述

| 项 | 内容 |
|---|---|
| 项目名 | 一程随行（along-trip） |
| 定位 | 行程规划类 App（C 端向），单人规划 + 多人协作 |
| 基础框架 | RuoYi-Vue3（v3.9.2，前端） |
| 前端技术栈 | Vue 3 + Vite + Element Plus + Pinia + Vue Router 4 + ECharts |
| 后端技术栈 | RuoYi-Vue（Spring Boot + MyBatis + MySQL + Redis） |
| 仓库结构 | 前端在 `RuoYi-Vue3-master/`；后端需另行拉取 RuoYi-Vue 源码 |

### 1.1 产品功能范围（MVP）

```
行程规划 App
├── 1. 行程管理    创建/编辑/删除行程（目的地、起止日期、主题色、状态）
├── 2. 日程编排    按天编排，景点/交通/住宿/餐饮日程项，拖拽排序  ← 核心
├── 3. 景点库      景点增删改查（名称/城市/经纬度/评分），供日程引用
├── 4. 地图选点    高德地图 POI 搜索 + 选点，回填经纬度（二期出地图总览）
├── 5. 预算管理    分类预算 vs 实际花费，占比图
├── 6. 协作分享    成员管理（owner/editor/viewer）+ 只读分享链接
└── 7. 工作台      登录后落地页 =「我的行程」卡片流
```

## 2. 技术栈与编码约束（硬性红线）

来自 `AGENT.md`，所有协作者必须遵守：

- **JavaScript**，禁止 TypeScript 语法
- **Composition API（`<script setup>`）**，禁止 Options API
- UI 只用 **Element Plus**（全局已注册），禁止引入新 UI 框架
- HTTP 一律走 `src/utils/request.js`，禁止直接用 axios、禁止硬编码后端地址
- 禁止修改 `src/utils/request.js` 核心拦截逻辑
- **禁止删除/修改 `permission.js` 中已有路由守卫逻辑**
- 列表页必须用 `<pagination>` 组件 + `queryParams.pageNum/pageSize`
- 字典值用 `<dict-tag>` 展示，数据用 `useDict()` / `getDicts()` 获取
- 权限控制用 `v-hasPermi` 指令
- 弹窗用 `el-dialog`，表单校验用 `el-form` rules
- 消息提示用 `ElMessage` / `ElMessageBox`
- 日期格式统一 `YYYY-MM-DD HH:mm:ss`
- 页面放 `src/views/{模块}/`，文件名 kebab-case；接口放 `src/api/{模块}/`，导出命名 `list/get/add/update/del + 资源名`
- 新增页面参考 `src/views/system/user/index.vue` 的风格

## 3. 现状盘点

### 3.1 已有（直接复用）
- 登录/注册/JWT/RBAC 权限体系（`v-hasPermi`）
- 布局系统：侧边菜单 + 顶栏 + 面包屑（`src/layout`）

- 代码生成器 `tool/gen`（后端配套生成 CRUD）

### 3.2 缺失（本次改造目标）
- 行程领域数据模型与接口
- 移动端风格布局（当前是 PC 后台风格）
- 地图能力（高德）
- C 端向首页 / 工作台
- 协作与分享机制

## 4. 已确认的技术决策（用户拍板）

| # | 决策点 | 结论 | 影响 |
|---|---|---|---|
| D1 | 后端 | **搭 RuoYi-Vue 官方后端** | 表结构遵循若依规范，吃代码生成器红利 |
| D2 | 界面形态 | **移动端风格** | 全站限宽卡片化改造，工作量集中在 layout |
| D3 | 地图 | **接高德地图** | 景点表预埋 lng/lat；需申请高德 key；上线前做地图合规检查 |
| D4 | 协作 | **完整协作** | 后端接口层按角色拦截（防绕过），前端只控制显隐 |

> 地图合规：国内地图必须使用有资质图商（高德满足）。涉及地图渲染前，需按 `geo-map-compliance-guard` 技能要求做合规检查。

## 5. 改造总思路

**保留权限/布局骨架，业务重心从「系统管理」换成「行程规划」。** 拆 4 层：

1. **数据层**：新增 6 张业务表（见 §6）
2. **接口层**：后端生成 + 自定义行程模块接口；前端新增 `src/api/trip/*`
3. **页面层**：新增 `src/views/trip/*`；首页换成「我的行程」工作台；全站移动化
4. **配置层**：菜单 / 字典 / 权限 SQL

> 后台管理系统功能（用户管理、系统监控等）保留代码但可从菜单中隐藏，方便开发期自查数据。

## 6. 数据库表设计（6 张核心表）

> 全部遵循若依规范字段：`id`(主键)、`create_by`、`create_time`、`update_by`、`update_time`、`remark`。下仅列业务字段。

### 6.1 `trip` 行程表
| 字段 | 类型 | 说明 |
|---|---|---|
| trip_name | varchar(100) | 行程名称 |
| destination | varchar(100) | 目的地 |
| start_date | date | 开始日期 |
| end_date | date | 结束日期 |
| theme_color | varchar(20) | 封面主题色 |
| status | char(1) | 状态（字典 `trip_status`：0草稿/1进行中/2已完成） |
| owner_id | bigint | 创建人（行程所有者） |

### 6.2 `trip_day` 日程表（按天）
| 字段 | 类型 | 说明 |
|---|---|---|
| trip_id | bigint | 所属行程 |
| day_no | int | 第 N 天（1 起） |
| trip_date | date | 当天日期 |

### 6.3 `trip_item` 日程项表
| 字段 | 类型 | 说明 |
|---|---|---|
| day_id | bigint | 所属日程 |
| item_name | varchar(200) | 名称（景点名/车次/酒店等） |
| item_type | char(1) | 类型（字典 `trip_item_type`：1景点/2交通/3住宿/4餐饮/5其他） |
| start_time | varchar(10) | 开始时间（HH:mm） |
| end_time | varchar(10) | 结束时间 |
| spot_id | bigint | 关联景点（可选，仅类型=景点时） |
| note | varchar(500) | 备注 |
| sort_order | int | 当日排序 |

### 6.4 `trip_spot` 景点库表
| 字段 | 类型 | 说明 |
|---|---|---|
| spot_name | varchar(100) | 景点名称 |
| city | varchar(50) | 城市 |
| address | varchar(200) | 地址 |
| lng | decimal(10,6) | 经度 |
| lat | decimal(10,6) | 纬度 |
| rating | decimal(2,1) | 评分 |
| intro | text | 简介 |
| image_url | varchar(200) | 图片 |

### 6.5 `trip_member` 行程成员表
| 字段 | 类型 | 说明 |
|---|---|---|
| trip_id | bigint | 所属行程 |
| user_id | bigint | 成员用户 |
| role | char(1) | 角色（字典 `trip_role`：1owner/2editor/3viewer） |

### 6.6 `trip_budget` 预算项表
| 字段 | 类型 | 说明 |
|---|---|---|
| trip_id | bigint | 所属行程 |
| category | char(1) | 分类（字典 `budget_category`：1交通/2住宿/3餐饮/4门票/5其他） |
| budget_amount | decimal(10,2) | 预算金额 |
| actual_amount | decimal(10,2) | 实际花费 |

### 6.7 业务字典
- `trip_status`：行程状态
- `trip_item_type`：日程项类型
- `trip_role`：协作角色
- `budget_category`：预算分类

### 8.3 各任务详细说明（含验收标准）

#### T1 拉取并启动 RuoYi-Vue 官方后端
- **目标**：从 gitee 拉取 RuoYi-Vue（Spring Boot 后端）到仓库同级目录
- **步骤**：建库 `ry`（含默认 `ry_*.sql` 初始化）→ 配置 `application-druid.yml`（MySQL）与 `application.yml`（Redis）→ 启动（默认 8080）
- **验收**：后端启动无报错；`/swagger-ui/index.html` 可访问

#### T2 前端与后端联调打通
- **目标**：前端通过 `/dev-api` 代理访问后端
- **步骤**：核对 `vite.config.js` proxy 端口 → 用 `admin/admin123` 登录 → 确认能拉取菜单/用户信息
- **验收**：登录成功跳转首页，侧边菜单渲染完整

#### T3 设计并落地 6 张业务表
- **目标**：按 §6 建表
- **验收**：`SHOW TABLES` 出现 6 张 `trip_*` 表，字段、注释、索引齐全

#### T4 编写行程模块后端接口
- **目标**：用若依代码生成器从 6 张表生成 CRUD 代码，再补自定义逻辑
- **自定义逻辑**：
  - 行程列表只返回「我参与的行程」（owner 或 member）
  - 日程按天分组查询（一次返回整趟行程的 day + item 树）
  - 日程项拖拽排序接口（更新 sort_order）
  - 协作权限校验：owner 全权；editor 可改日程/预算；viewer 只读
- **验收**：所有接口在 Swagger 中可调通，权限校验生效

#### T5 菜单/字典/权限 SQL
- **目标**：SQL 插入菜单（`trip/index`、`trip/day`、`trip/spot`、`trip/budget` 等，component 路径写 `trip/xxx`）、业务字典（§6.7）、按钮权限标识（`trip:trip:add` 等）
- **验收**：admin 刷新后菜单可见、字典加载成功

#### T6 前端 trip 模块 api 与基础组件
- **目标**：`src/api/trip/` 六个 js 文件，全部走 `request.js`
- **验收**：`npm run dev` 无报错，接口函数导出规范（list/get/add/update/del + 资源名）

#### T7 移动端布局改造（全站移动化）
- **目标**：全站改移动端风格
- **要点**：内容区限宽 `max-width: 480px` 居中、深色底衬托；侧边栏折叠为抽屉/顶部切换；表格列表改卡片；按钮/输入/弹窗触屏尺寸；**不动 `permission.js` 路由守卫**
- **验收**：浏览器窄窗口下全站可用、视觉为移动 App 风格

#### T8 登录/注册页移动端美化
